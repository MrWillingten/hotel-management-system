# OWASP ASVS 5.0 – Level 1 self-assessment

**Standard:** [OWASP Application Security Verification Standard 5.0.0](https://github.com/OWASP/ASVS/tree/v5.0.0)
(May 2025), every requirement marked Level 1 (70 requirements). The
requirement IDs and the wording summarised below come from the official
CSV file of that release.

**Scope:** the web application, the JSON API, the command-line tools, and
the provided deployments (Waitress on localhost, Docker + Caddy, the Windows
program). **Version assessed:** 1.0.0 (Sprint 6, story 6.6). **Method:** we
read the code and configuration, and cite automated tests and documents as
evidence.

Result: **58 met · 12 not applicable · 0 open**. Three gaps found during the
assessment were fixed in the same story (marked *fixed in 6.6*).

Legend: ✅ met · ➖ not applicable (the feature does not exist) · *notes*
explain limits we accept.

| V1.3.2 | No `eval()` / dynamic code execution | ✅ | No `eval`, `exec` or template rendering of user strings (Bandit runs in CI). |
| V1.5.1 | Safe XML parser configuration | ➖ | The application parses no XML. |

|---|---|---|---|
| V3.2.1 | Content is not rendered in the wrong context | ✅ | `X-Content-Type-Options: nosniff` and a strict CSP on every response. | V3.5.2 | When relying on CORS preflight, no non-preflighted calls | ➖ | The design does not rely on preflight (V3.5.1 applies). |
| V3.5.3 | Sensitive functions use POST, not GET | ✅ | Every change is a POST (including logout and preferences); the API is GET-only and read-only. `e2e/test_auth_flow.py::test_logout_requires_post_and_csrf`. *Note:* opening the two-factor page creates a *pending* secret for the signed-in user. That is harmless: nothing is enabled until the user confirms with a code over POST. |

## V9 Self-contained Tokens

The only self-contained token is Flask's signed session cookie. It carries
the CSRF secret, flash messages and the pending sign-in challenge; it never
carries the identity.

| ID | Requirement (summary) | Status | Evidence |
|---|---|---|---|
| V9.1.1 | Signature/MAC verified before use | ✅ | `itsdangerous` HMAC; tampered cookies are ignored. |
| V9.1.2 | Algorithm allow-list, no `none` | ✅ | The application fixes the algorithm; the token cannot choose it. |
| V9.1.3 | Keys from trusted, pre-configured sources | ✅ | A random secret key in the data folder (W2); no key is ever taken from a token. |
| V9.2.1 | Validity period enforced | ✅ | CSRF tokens expire after 8 h; the sign-in challenge expires server-side after 5 min (`integration/test_two_factor.py::test_the_code_step_expires_after_five_minutes`). |
